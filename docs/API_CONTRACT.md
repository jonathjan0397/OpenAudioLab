# Proposed API contract v1

Base: `https://<backend-host>:50555/api/v1`, or the configured HTTPS proxy origin forwarding to port 50555. Hostname and frontend origin are deployment inputs, not known values. OpenAPI generated by implementation must match this document.

Protected routes use `Authorization: Bearer <per-user access token>`. Worker and administrator APIs use separate scopes. Authenticated user ID comes only from verified credentials, never a request's user_id field.

## Routes

| Method | Route | Purpose |
| --- | --- | --- |
| GET | `/health/live` | Public minimal process liveness |
| GET | `/health/ready` | Minimal dependency readiness; 503 when unavailable |
| GET | `/models` | Enabled/reviewed models, capabilities, availability and required notices |
| GET | `/models/{model_id}` | Exact revision and supported controls |
| POST | `/jobs` | Validate and enqueue; 202 with Location header |
| GET | `/jobs` | Owner-only cursor-paginated history |
| GET | `/jobs/{job_id}` | Owner-only status, stages, attempts and artifact metadata |
| GET | `/jobs/{job_id}/events` | Owner-authorized SSE; replay with Last-Event-ID |
| POST | `/jobs/{job_id}/cancel` | Idempotent cancellation request |
| POST | `/jobs/{job_id}/retry` | New bounded attempt for failed/cancelled job; idempotent |
| GET | `/jobs/{job_id}/artifacts` | Owner-only retained assets |
| POST | `/artifacts/{asset_id}/download-url` | Owner-authorized short-lived download link |

Worker routes under `/internal/v1` include authenticated registration, heartbeat, attempt claim, event update, upload authorization/finalization, completion and failure. Every mutation requires current worker identity, matching assignment, and the attempt's lease token. Administrator registry/worker/drain endpoints remain separate from user routes. Do not expose secrets in model or worker discovery.

No `/lyrics/generate` route, backend LLM credential, or lyric reasoning dependency belongs in this service.

## Create job

Require an `Idempotency-Key` header (opaque bounded length; scope to owner and route). Same key+same normalized request returns the original accepted result; same key+different request returns 409. Retain keys for at least 24 hours and document expiry.

```json
{
  "operation": "music.generate",
  "model_id": "ace-step-1.5",
  "music_description": "Acoustic country, warm baritone, fingerpicked guitar, restrained first verse, expansive final chorus.",
  "lyrics": "[Verse]\nMorning settles on the pine\n\n[Chorus]\nWe find our way in time\n",
  "lyrics_origin": "frontend_llm",
  "instrumental": false,
  "duration_seconds": 120,
  "seed": 7,
  "controls": {},
  "outputs": ["mix_wav", "mix_mp3"],
  "artist_profile_version_id": null,
  "client_reference": "optional-external-draft-id"
}
```

`lyrics_origin`: `human`, `frontend_llm`, or `mixed`, metadata only. Require nonempty lyrics for vocal jobs; require lyrics absent/null/empty for instrumental jobs. Reject contradictory inputs and unknown fields. JSON parsing may decode escapes, but preserve the resulting lyric string verbatim; hash its UTF-8 representation. Do not trim or normalize line endings.

`controls` uses a versioned model-specific schema published in model discovery. Unknown or unsupported controls return 422. Seed and duration are accepted only when supported by that adapter; discover supported ranges per release. Requested duration is a target when the engine cannot guarantee exact output. Any deterministic model mapping must be documented. Model revision resolves server-side to a pinned approved release and is frozen in the job; clients cannot request arbitrary URLs or Python code.

`style_prompt` (optional, free text, max 2000) is the style-keyword lane, distinct from `lyrics` and `music_description`. Public vocabulary: `GET /styles/cheatsheet` returns curated dimension categories (Moods, Eras, Instrumentation, Vocals, Tempo & Energy, Genres) plus one category per taxonomy family (358 subgenre keywords across 17 sections, versioned by `app/style_data/style_taxonomy.json`) and `lora_tags` for released trained adapters. `POST /llm/style-prompt` composes descriptions from that same canonical vocabulary (its system message embeds the keyword list; disable per deployment via SiteSetting `style_keyword_prompt=off`). At generation the worker normalizes `style_prompt` through the taxonomy alias map: matched terms are replaced by their canonical subgenre captions and unmatched words pass through; junk words drop; the combined caption (`music_description`, then resolved style text, trimmed to 2000 chars) is the engine's non-lyric prompt. Lyrics remain a separate field and are never part of this folding. `song_idea` stays recipe/manifest metadata and does not reach the engine. The submitted `style_prompt` string is stored verbatim in the job recipe for recreation.

202 example (illustrative UUIDs):

```json
{
  "job_id": "8a7b7c49-3e08-4f0d-a138-b89ec60ea660",
  "status": "queued",
  "model_id": "ace-step-1.5",
  "model_revision": "<pinned-upstream-commit>",
  "status_url": "/api/v1/jobs/8a7b7c49-3e08-4f0d-a138-b89ec60ea660",
  "events_url": "/api/v1/jobs/8a7b7c49-3e08-4f0d-a138-b89ec60ea660/events",
  "poll_after_seconds": 3,
  "required_notices": []
}
```

Job details include `created_at`, `started_at`, `finished_at`, `attempt_number`, `stage`, `progress` (nullable 0..1), `progress_source`, `lyrics_sha256`, safe `error`, `artifacts`, `assets_expired_at`, and model/policy snapshot. Do not invent exact queue positions or ETA; return null when unavailable. Keep native audio metadata distinct from requested settings.

SSE events include `id`, `event` and JSON `data` containing job/attempt IDs and persisted stage/status. Reconnect/replay is authorized per job, with bounded replay retention and a documented resync event. Native browser EventSource cannot set bearer headers: use authenticated fetch streaming, or the frontend BFF. Never put long-lived access tokens in query strings. Polling is the first milestone fallback.

## Errors and lifecycle

Error envelope: `{"error":{"code":"MODEL_UNAVAILABLE","message":"...","request_id":"...","details":{}}}`. Do not expose provider responses, traces, credentials or internal filesystem paths.

Use 401 for unauthenticated, 403 for restricted capabilities, 404 for nonexistent or other-owner resources, 409 for idempotency/state conflict, 410 for expired owned assets, 413 for body limits, 422 for invalid controls/lyrics, 429 for rate or concurrency limits (Retry-After), and 503 for an unconfigured/unhealthy required engine or dependency. A ready model with temporarily busy capacity can accept queued work. Models not configured or not licensed must not be queued as if ready.

Retries preserve canonical input and model revision and create a new attempt with a fresh lease. No automatic cross-model substitution. Cancellation responses include effective state and whether upstream compute termination is supported. A late success after confirmed cancellation is discarded and cannot publish assets.

Download URLs include server-calculated expiry no later than artifact expiry and are short-lived, typically five minutes. Range requests and actual MIME metadata support browser playback. Backend CORS must explicitly allow configured origins, Authorization, Content-Type and Idempotency-Key, exposing Location and Retry-After where needed.

## Frontend integration sequence

1. Frontend's own LLM produces lyrics; user edits and approves them within the frontend workflow.
2. Frontend obtains model capabilities and notices, then submits the final lyrics/music direction with a per-user token and one idempotency key per intentional submission.
3. On 202, retain job ID and switch to progress view; poll or fetch-stream events.
4. On success, request authorized preview/download URLs. Expired URLs can be refreshed while assets remain retained.
5. Cancellation/retry use documented endpoints. The frontend's LLM service can be unavailable without preventing submission of already-written lyrics or instrumental jobs.


## Expanded backend service routes (capability specification)

All paths below share `/api/v1`. All resource operations are authenticated and owner/ACL scoped. UUIDs are opaque. Metadata routes are synchronous; preparation, training, processing and rendering return 202 with common `/jobs/{job_id}` status/events URLs. Use operation-discriminated request schemas rather than one permissive bag of fields. Missing optional fields use documented defaults; unknown fields fail validation.

| Method | Path | Behavior |
| --- | --- | --- |
| POST / GET | `/projects` | Create/list owned projects |
| GET / PATCH / DELETE | `/projects/{id}` | Read/update/tombstone project; ETag for edits |
| POST / GET | `/projects/{id}/versions` | Create immutable version manifest/list versions |
| GET | `/projects/{id}/versions/{version_id}` | Read owned version and lineage |
| POST | `/projects/{id}/restore` | Point active version to existing immutable version with concurrency guard |
| POST | `/assets/uploads` | Allocate constrained private upload session |
| POST | `/assets/uploads/{upload_id}/complete` | Validate/finalize or queue probe; ownership checked |
| GET / DELETE | `/assets/{id}` | Metadata/revoke and schedule policy-aware deletion |
| POST | `/exports` | Queue explicit WAV/MP3/WAV-stem/ZIP export |
| POST / GET | `/artist-profiles` | Create/list private artist profiles |
| GET / PATCH / DELETE | `/artist-profiles/{id}` | Read/update/revoke and queue deletion |
| POST / GET | `/artist-profiles/{id}/versions` | Add reference/style configuration candidate/list immutable versions |
| GET | `/artist-profiles/{id}/versions/{version_id}` | Candidate mechanism, compatibility, evaluation and provenance |
| POST | `/artist-profiles/{id}/activate` | Activate evaluated compatible version; optimistic concurrency |
| POST / GET | `/datasets` | Create/list owned training datasets |
| GET / PATCH / DELETE | `/datasets/{id}` | Metadata, draft edits and policy-aware deletion |
| POST / DELETE | `/datasets/{id}/assets/{asset_id}` | Attach/detach authorized asset while draft |
| POST / GET | `/datasets/{id}/versions` | Freeze/list immutable source dataset snapshots |
| GET | `/datasets/{id}/versions/{version_id}` | Source/prepared manifest and reports |
| POST | `/datasets/{id}/prepare` | Queue preparation of a frozen source version |
| GET | `/training-recipes` | Verified base/recipe compatibility, requirements, controls and limits |
| POST | `/training-jobs` | Validate budget/compatibility and queue actual fine-tuning |
| POST | `/artist-profiles/{id}/evaluations` | Queue candidate evaluation with fixed prompts/holdout |
| POST | `/jobs/{job_id}/resume` | Resume supported interrupted training from a valid checkpoint; otherwise reject |
| GET | `/usage` | Own allowances, reservations and usage records |

Training/evaluation records use common job reads/events/cancellation. Profiles expose evaluation records/artifacts through their version metadata. Manual reference/style versions are explicitly evaluated for their own mechanism; they cannot masquerade as fine-tuned versions. Resume is not a generic retry: validate checkpoint compatibility, dataset/base/recipe hashes and budget. Training retries are explicit, bounded and disabled automatically by default.

Existing `/jobs` admits discriminated operations including `music.generate`, `music.variation`, `music.extend`, `music.replace_section`, `music.remix`, `audio.separate`, `audio.analyze`, `audio.process` and `audio.render` as adapters become available. Specialized `/exports`, `/training-jobs`, dataset preparation and evaluation endpoints are canonical creation routes for those operations; they all return the common job envelope. Do not create duplicate jobs if a frontend retries a creation request.

Generation adds `operation=music.generate`, optional exact `artist_profile_version_id`, and `outputs`. `outputs` includes `mix_wav`, `mix_mp3`, `stems_wav`, `stems_zip`; export options follow OUTPUT_SPEC.md. Profile ID aliases may be supported only if resolved/frozen at admission; explicit version IDs are preferred. Backend checks ownership and base-model compatibility before dispatch.

Edit requests identify owned source version, sample/time range and supplied final lyrics when relevant. Freeze sample rate/time interpretation and source checksum; reject out-of-range spans. Processing/render requests use safe versioned DSP/session schemas; they cannot carry shell commands, arbitrary plugin code or filesystem paths. Frontend conversational commands must map into these validated operations.

Training request example:

```json
{
  "artist_profile_id": "<owned-profile-uuid>",
  "prepared_dataset_version_id": "<frozen-prepared-dataset-uuid>",
  "base_model_release_id": "<approved-release-id>",
  "training_recipe_id": "<verified-recipe-revision>",
  "components": ["musical_style"],
  "parameters": {},
  "budget": {"max_gpu_seconds": 3600, "max_wall_seconds": 7200},
  "seed": 7
}
```

Numbers above illustrate request shape, not expected training cost or recommended model settings. Server limits cap any client request. Recipe discovery specifies valid parameters/components, measured hardware support, minimum dataset requirements, checkpoint/resume behavior and evaluation support. Add specific errors for unsupported capability, incompatible profile/base, invalid dataset, rights record required, insufficient allowance, training recipe unavailable and deleted resource. Never return secret model paths or raw provider failure text.

Future backend-only extensions include revocable collaboration grants/comments, signed webhook subscriptions/delivery history, MIDI jobs and advanced session automation. They are not a bundled frontend or a commitment that the first selected engine implements them.
